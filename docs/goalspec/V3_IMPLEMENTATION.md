# GoalSpec v3 implementation and evaluation protocol

This iteration is local only, retains the original shared $500 ledger, and keeps the pinned actor, user, predictor and embedding identities. It does not promise improvements before measurement. V1 and v2 source archives, outcomes and cost reservations remain immutable.

## Architecture

PASTE is the June 2026 revision of *Parallelizing Tool Execution and LLM Generation for Low-Latency Agent Serving*, https://arxiv.org/html/2603.18897v3. Salesforce is the July 2026 *Speculate with Memory: Lossless Acceleration for LLM Agents*, https://arxiv.org/html/2607.12236v1. APIGen is a separate dataset. These are paper-based implementations; no verified author reproduction or hosted-API equivalent of PASTE's GPU scheduling hooks is claimed. See V3_SOURCE_AUDIT.md for component-level fidelity.

The shared runtime now retrieves local workflows before remote prediction, binds unambiguous scalar arguments from current sources, caches tool validators, and checks expected exposed latency savings before admitting reads. An evidence-visible session can wait at most 80 ms per deterministic hop, at most two hops and two new observations per actor boundary. All actual reads still pass admission, authorization, ownership and freshness checks. There are no speculative mutations. Verified observations are distinct runtime context, not fabricated function results. Their typed provenance and exact historical context persist into later actor decisions.

Full successful and failed public episodes, contrastive transitions, prediction misses and recurring confusion hints are frozen separately from business evidence. The memory artifact uses only prior custom training and development runs. Historical entities do not become current arguments without current source binding. Contextual retrieval includes recent observations and decisions. The current hosted implementation does not claim Salesforce's complete original training pipeline.

The actor compiler preserves complete real continuation items and tool IDs. Stable domain policy stays before changing runtime context. Small contexts use an equivalent fast compilation path; oversized contexts retain the previous bounded compiler. All four research arms use the same actor transport correction: ordinary final response text, with tools through the API, instead of the upstream text protocol's incompatible JSON-only instruction. Domain business policies remain intact.

## Admission estimates

Closed v2 development-2 data: 53 speculative gateway reads, median 28 ms; 24 validations, median 8.5 ms. Native authoritative read timestamp differences were too coarse to establish positive exposed tool time. Initial exposed tool saving is therefore zero, validation 8.5 ms and scheduling allowance 1 ms. Lossless paper arms abstain where this is nonprofitable. They are explicitly profit-abstaining controls on these cheap native tools, not claimed active upstream reproductions.

GoalSpec's effective actor-round saving starts at 1,000 ms as an engineering estimate that includes uncertainty about whether the actor will skip a round. It is not a calibrated probability or measured gain. Development evidence must assess actual skipped calls, added work and total latency. Separate prediction replay can test predictor quality even when the live admission policy declines execution.

## Live study

Development-1 completed all 16 trials, with native success 3/4 for each arm. Two API failures remain failures with unresolved charges. The first GoalSpec integration exposed a native wire-envelope mismatch, so its proposed reads did not become validated evidence. Development-2 repairs that boundary using captured native ToolMessages and replaces full-database snapshot copying with complete audited dependency projections. Original native results, ownership checks, direct-mutation freshness checks and legacy full snapshots remain covered by tests. Offline snapshot timing is separate from paid task latency.

Development-2 completed all 16 trials: base and PASTE 2/4, Salesforce and GoalSpec 3/4. GoalSpec still had higher mean live latency. Retail task 13's differing simulator requests qualify the apparent accuracy gap; airline task 39 has a separately documented potential gold-policy mismatch. Native scores remain unchanged. A further socket failure occurred despite fresh connections. The next frozen build adds one explicitly budget-reserved retry only for UND_ERR_SOCKET, with host checks and unknown-charge retention, equally across all research Responses roles and arms. It also corrects eligibility-before-calibration, numeric request ordering, typed identity-to-profile binding and pure-calculator classification. These changes must be tested and measured; they do not establish improvement by themselves.

Development-3 completed 16/16 trials with no new unresolved charges. Native success was base 2/4, PASTE 3/4, Salesforce 2/4 and GoalSpec 3/4; mean live times were 48.965, 47.569, 51.051 and 56.903 seconds. GoalSpec made 27 authoritative and 10 speculative calls, with three exact promotions and five exposed evidence entries. This did not establish a latency or physical-call advantage. Completed traces show unnecessary user clarification after early profile evidence. A final compact-context amendment prefers authorized reads for record details needed by the current request, while preserving unresolved choices and required consent. The sole confirmation measures that amendment; development-3 does not. The admission configuration and all native policies, users, tools, models and memory remain unchanged.

Four research arms are base, PASTE-style lossless speculation, Salesforce-style lossless memory speculation, and goal/evidence-visible GoalSpec. Research arms are dependency composition, not an application mode switch. The three original v1/v2 arms remain reproducible.

Use unchanged pinned upstream retail and airline tasks, native user simulation, environment state and ALL reward evaluation with strict replay. Retail's judge uses the specified research teacher gpt-5.4-2026-03-05, differing from the upstream default gpt-4.1-2025-04-14. Actor reasoning stays medium, output cap 4,096. Native max_steps is 200 for every arm. User output cap is 1,024. A hash-bound readiness handshake precedes trial clocks. One native trial runs at a time to avoid cross-arm local contention. Startup and evaluation latency are reported separately from live actor/user execution and drain.

Earlier public replay exposed all published retail and airline task IDs. The new live trials are fresh executions on a fixed official-task subset, not previously unseen tasks or an official full leaderboard score. V3 confirmation IDs are disjoint from v3 development and fixed before development outcomes. Historical public trajectories are excluded from the frozen v3 memory and are not used to choose task IDs or tune against confirmation results.

At most three development rounds use four tasks, one trial and all four arms. Confirmation uses up to 16 balanced tasks and two trials per arm. Size uses completed development costs and remaining heldout allocation only. Every declared slot is reserved before dispatch. Failures, including infrastructure, API, budget and evaluation failures, remain reported and are never replaced. There is one final confirmation cohort. Further changes after confirmation require a new openly labeled study, not retrospective rescoring.

Report native task success/reward, tool execution errors, exact next-tool and argument prediction where defined, physical authoritative/speculative/validation calls, useful and wasted work, latency with sample sizes, billed and unresolved cost, paired differences and task-clustered uncertainty. Native non-error tool responses are not a proxy for policy correctness or gold-path accuracy. Replay timings and compiler microbenchmarks remain separate from live latency.
