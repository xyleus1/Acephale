# Native execution replay preparation

There are two distinct unpaid follow-up analyses. The [legacy checkpoint plan](LEGACY_REPLAY_ANALYSIS_PLAN.md) scores the new v2 frozen goal cache on all 213 previously observed v1 checkpoints, using seven prediction conditions and seven identical-pool controls. Native execution replay instead executes saved live candidate predictions against fresh native states while holding the original actor action tape fixed. The existing native replay accepts a completed native cohort, its exact fixture manifest, and immutable live event logs. It does **not** accept `frozen-goals.jsonl` or the seven-condition prediction output.

Native replay can therefore check v2 development-2 or confirmation's recorded live goal-conditioned candidates. It cannot establish native execution behavior for the newly inferred 213 legacy goals without a separate adapter that generates and binds candidate actions from those goals. The 24-case `scripts/goalspec-execution-replay.ts` uses temporary file fixtures and is only a scheduler demonstration; it cannot substitute for native replay.

The existing real-native implementation is `research/goalspec/scripts/native_execution_replay.py`, backed by `scripts/goalspec-native-execution-replay.ts`. The Python side creates fresh native states from the original fixtures, replays every observed authoritative call, requires tool observation equality, and compares the final native database against the saved original. It keeps original success and termination labels. Base-arm runs and speculative-arm runs with no actor decisions are skipped by the existing driver, so replay coverage must always be reported separately from the full primary denominator. Replay latency is local tape-execution time with no model work and is not live trial latency.

Source inspection found a v2 compatibility issue in the original runner. Its event reader includes `candidate_prediction` records regardless of `admission:false` and only excludes the old reason `argument_or_scope_validation`. V2 emits `invalid_low_confidence_or_already_observed`; those recorded rejected predictions must not become newly eligible replay reads. Development-2 contains 158 such neutral events and 83 GoalSpec events, separate from four and one scheduler-rejected candidates.

The report-local [Python adapter](native_execution_replay_v2.py) reuses the frozen native orchestration through a subprocess dependency scoped to the imported module. Only its Node entrypoint is replaced by the [v2 event reader](native_execution_replay_v2.ts). The frozen runtime and original replay scripts remain unchanged. The reader admits only records with `admission === true`, checks each source event's immutable chain and identity, and verifies scope and binding paths against the prior execution frame at that same boundary. Its candidate-event input hash is preserved as recorded; asynchronous goal adoption can differ from the earlier frame, so full frame-hash equality is not claimed.

The adapter requires the complete confirmation receipt, exact outcome and fixture identities, source/input file hashes, and current execution matching final source tree `93c2d973b2164ebed9e3a713541586722e4af91ef06f8b811dd8907ea1a09166`. The first `research_manifest` event must hash the saved source service manifest and own exactly all 48 declared run IDs; the final event must be `service_closed`. It writes a deterministic input manifest before launching the local replay. All declared trials appear in its coverage report. Original unadmitted candidates and admitted candidates without a corresponding recorded actor turn remain explicitly counted as exclusions. Originally admitted candidates are subject to the scheduler again, so new scheduler-admission counts are also reported; replay timing differs from the original concurrent inference process. The inherited frozen `report.json` wording about predictions captured before the original actor decisions does not apply to asynchronous v2. Candidates are replayed at their numbered boundaries without claiming that original availability timing.
