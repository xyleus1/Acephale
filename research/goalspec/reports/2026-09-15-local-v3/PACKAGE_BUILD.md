## Byte verification and source boundaries

The v3 builder validates both outer source/input ZIP hashes and the exact manifest-bound member names, bytes and hashes. Historical original input paths are metadata only and are never dereferenced or used as extraction destinations. Frozen inputs come from the original `inputs.zip`; both ZIPs are embedded byte-for-byte.

The verifier rejects traversal/absolute/backslash archive names, duplicate/case-fold collisions, links, directories, encrypted members, undeclared nested ZIPs, credential-like names, environment files and dependency/database caches. It scans text, including extensionless inputs according to original filename metadata, for actual-looking keys or long credential fields. Errors show paths rather than secret text. Do not mutate originals or bypass a concrete secret finding.

Root verified all 544 captured source files and 257 inputs at confirmation closure, after original replay, and immediately before final documentation work. The builder independently checks current protected execution identities before and after ZIP construction. In the actual capture, `report_v3.py`, `archive_v3.py` and the original TypeScript importer are execution files and remain unchanged. Their filenames do not create an exception.

`currentAllowedSources` contains only the 15 exact sources that the capture categorized as analysis or artifact_export. Selected new executable helpers require exact `sourceOverlays` hashes and reasons with `frozenSha256: null`; they are disclosed in `SOURCE_OVERLAYS.json`. These helpers were not used by the frozen native confirmation. Correction helpers are separately bound by the correction plan and are not silently substituted into the original replay.

Changed captured documentation requires exact original/current hashes and reasons in `documentOverlays`, disclosed in `DOCUMENTATION_OVERLAYS.json`; the original versions remain inside source.zip. This mechanism cannot relabel runtime execution. The final three handoff/log/decision document hashes must be refreshed after root's authorized edits.

Each selected file is hashed before copying, streamed into the new ZIP, checked again afterward, and every final ZIP member is independently read back and SHA256 verified. Package metadata excludes self-hashing; external sidecars bind the complete ZIP and internal manifest. An active shared-ledger lock blocks packaging. Only a closed copied journal with its pinned closure receipt is allowed.
